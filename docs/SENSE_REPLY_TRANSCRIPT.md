# IoT for Energy Grid

## Summary

### Flow Summary

Guest lecture from an energy IoT consulting firm on software, edge AI agents and smart grids, followed by Q\&A and project briefs: market analysis for first years, agent KPI assessment for second years.

### Why IoT and Software Matter in Energy

- IoT lets companies monitor the grid constantly and apply rules via software instead of costly hardware  
- Distributed renewables strain the grid, which must stay balanced at every moment to avoid blackouts  
- Speaker 1: AI will not soon replace consultants, but uncoordinated AI coding on a 15-developer project cut control  
  - Expects fewer developer roles, more roles managing AI use and team coordination  
- Biggest unsolved problem: fast monitoring and managing terabytes to petabytes of grid data

### Energy Transition and Selling to Clients

- Speaker 1 sees human behavior mattering more than technology; tech helps people understand what to do  
- Ideal is producing near consumption; energy communities get incentives for consuming when energy is produced  
  - Batteries are key to shifting solar use to night  
- Selling long-ROI projects can take months or years; must reach the right stakeholder across IT and business  
- Airport energy monitoring project: hardest part was connecting legacy devices with differing protocols  
  - Client gained visibility on spending and predictive maintenance of device failures

### Edge Agents Platform Demo

- Edge gateways collect field data to a cloud IoT platform that manages software, health and security of devices  
- Firm (transcribed as SensorApply) is building infrastructure to deploy AI agents directly on edge gateways  
  - Agents run on edge for scalability; LLM calls go to Mistral (model heard as 'Dextral')  
  - Plans to test local models (Gemma, Qwen) as fallback if cloud connection is lost  
- Demo: digital twin of a building with solar, grid and battery; an agent decides battery charge and discharge  
- Hardware choice (GPU vs Raspberry-class) is set with the client via a POC, driving cost

### Student Project Briefs

- First years: market analysis of IoT platforms that deploy agents to the edge, with no dataset provided  
  - Identify and segment clients, map competitors, define a business model, interview potential clients  
- Second years: assess two JSON datasets, cost agent only vs cost plus sustainability agent  
  - Define KPIs with formulas, quantify cost trade-off of sustainability, suggest system changes  
  - README PDF explains fields such as PV power and PV fault  
- With two agents, an orchestrator workflow picks one battery power value using agent proposals and scores  
  - Scores cover cost, resilience, comfort, sustainability; inference cost not yet assessed  
- Learning from historical cases could be included as a student proposal
